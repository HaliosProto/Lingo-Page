# Known limitations

This local release candidate is intentionally bounded. These are known limitations, not promises for the public product.

- Mock mode is the verified default. It is deterministic and visibly marked; it does not measure real provider quality.
- Real providers are backend-only and require separate accounts, keys, default models, and model allowlists. No live real-provider call has been made in this workspace; protocol conformance is covered with mocked boundaries.
- Compatible APIs change over time. Base URLs were verified on 2026-07-15, but provider model behavior and JSON-mode support still require owner-run smoke tests before reliance.
- Model discovery is optional, explicit, cached, and allowlist-filtered. It does not automatically enable newly listed models or determine translation quality.
- There is no production identity, account, durable quota, billing, or multi-user authorization model yet. Local development auth is intentionally limited to the loopback helper; staging and production require authentication.
- Automated browser coverage uses the managed Chromium runtime. Branded Chrome must be tested manually and is reported separately.
- Automatically translated copies require a separate optional grant for the current HTTP(S) origin because `activeTab` does not transfer to a newly created tab. A denied user can duplicate the page and invoke Lingo Page manually there; broad all-site access is never requested.
- Translation is conservative: browser-internal pages, the Web Store, excluded domains, sensitive pages in privacy mode, passwords, payment/security fields, editable controls, code, scripts, styles, hidden content, numeric-only strings, URLs, and extension-owned UI are excluded.
- Only eligible visible text nodes in the top-level page are handled. Shadow DOM, canvas-rendered text, images, cross-origin frames, and iframe contents are not translated by this MVP.
- The local API quota and rate counters are process-local and reset when the worker restarts. They are not an enforcement boundary for production.
- The custom compatible provider restricts configuration to backend-controlled HTTPS public or loopback URLs, but it is an advanced local feature and is not a general-purpose proxy.
- Page-owned sessions support repeated views, explicit change scans, changed-only updates, acknowledged copy isolation, sanitized full-page comparison, reload reconstruction, and bounded restored-tab reattachment. Physical sleep/wake, tab-discard/BFCache behavior, and framework-specific complex SPA persistence remain incompletely verified.
- The diagnostics export is intentionally limited to operational metadata and counts. It is not a crash dump or a full browser trace.
- Deployment, store publication, public hosting, provider-key provisioning, and branded-Chrome approval are out of scope for this milestone and require explicit owner approval.
- Eligibility now rejects inherited/variant editability and hidden ancestors, and request context excludes descendant text; broad real-site and shadow-DOM coverage remains incomplete.
- Provider response bodies are not independently size-bounded and the provider timeout scope currently ends before JSON body consumption; validate and harden in a narrow task.
- The 2026-08-03 `pnpm audit` and `pnpm audit --prod` commands both report six high advisories across `adm-zip`, `shell-quote`, and two vulnerable `brace-expansion` version lines, all reached through the pinned WXT/web-ext/ESLint build and development toolchain. These Node tools are not bundled into the produced Chrome extension, and the repository security/bundle scan passes, but the lockfile remains affected. Dependency upgrades or overrides require a separate approved compatibility task.
- The comparison preserves common semantic reading structure rather than site CSS or pixel-perfect layout. It omits active forms, input values, media/canvas, arbitrary styles, scripts, frames, embedded objects, hidden content, and interactive state. Safe resolved HTTP(S) images/links follow the documented no-referrer policy.
- Managed Chromium screenshots cover completed, retained-original, reapplied, partial, no-change, changes-found, updated, delayed-hydration copy readiness, light RTL/LTR, dark, linked/unlinked scroll, divider, swapped, and narrow comparison states. Branded Chrome was connected, but its control boundary blocks `chrome://extensions`, so the unpacked build, production permission prompt, Wikipedia, screen reader, 400% zoom, contrast/high-contrast, and owner acceptance remain unverified.
- Saved reduced motion now applies in popup, Options, and comparison surfaces and is covered in managed Chromium; OS-level and branded-Chrome visual confirmation remain manual.
- Chromium heap snapshots are not leak proof. The very-large final-original snapshot remained elevated without forced collection; repeatable GC-aware lifecycle profiling remains a dedicated follow-up.
- Comparison handoff is single-use. Reload before retrieval, service-worker failure during handoff, mismatched navigation, oversized sessions, or invalid data fail closed instead of reconstructing the session.
- Reload recovery is exact-tab bound. Browser-restart/recently-closed recovery can transfer an unexpired session to one new tab ID only with exact-origin access, Chrome restoration evidence, strong identities/fingerprints, and no competing candidate. Multiple same-URL closed entries are intentionally ambiguous and may reject a legitimate restore. The owner branded-Chrome restart/Ctrl+Shift+T test failed at `fa2135b`; the corrected build has managed-Chromium evidence but still requires owner Tests A-E. Physical sleep/wake, tab discard, and BFCache certification remain unavailable.
- An ambiguous in-flight provider request is never auto-replayed after lifecycle loss. Completed cached values reconstruct, while remaining work is paused for deliberate user resume.
- SPA route handling is conservative: path/query/origin content changes invalidate the recovery record. Same-URL compatible DOM replacement can rebind unique matches, but framework-specific React/Vue/Angular certification remains fixture-based rather than exhaustive.
- Forced-GC leak proof, branded-Chrome recovery screenshots, screen-reader behavior, 400% zoom, high contrast, and OS-level reduced motion remain manual evidence.
- Translation quality is verified structurally with deterministic/synthetic fixtures; no live-provider or human linguistic-quality claim is current workspace evidence.
- Automatic classification, source-language carryover, truncation, and terminology inference are bounded heuristics. They may warn on legitimate output or miss subtle semantic errors; automatic review is one-pass and non-authoritative.
- Site glossary scope is local to an exact HTTP(S) origin. There is no account, cloud/team glossary, remote translation memory, autonomous correction learning, or cross-device synchronization.
- Document terminology memory is page-session-only and currently seeded by relevant explicit glossary decisions; broader validated term extraction remains future evaluation work.
- The in-app Browser can inspect extension pages when its runtime is connected, but managed Chromium remains the reproducible automated browser gate. Branded Chrome, formal screen reader/contrast, and live-provider smoke checks remain separate owner evidence.
- The Milestone 3 managed performance run completed 2,206 segments in 1,249 ms versus the final M2 492 ms result and observed an 82 ms longest task. The structured policy/context/validation/quality path remains bounded and clean pages make zero review calls, but this is a material documented latency regression against M2 and exceeds the aspirational 50 ms task target.
- The in-app Browser runtime could not initialize in the current Windows sandbox because profile traversal failed with `EPERM` at `AppData`; managed loaded-extension Playwright supplied the M3 UI evidence. This is a tooling limitation, not evidence that the product fails in branded Chrome.
